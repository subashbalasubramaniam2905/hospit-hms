# Free online demo: GitHub Pages + Render + Supabase

The online demo uses three free services:

| Part | Service | What it costs |
| --- | --- | --- |
| Web app | GitHub Pages | Free |
| API (Spring Boot server) | Render, free web service | Free. Sleeps after 15 minutes without visitors; the next visit waits about a minute while it starts. |
| Database | Supabase, free Postgres | Free. A project with no activity for 7 days is paused; restore it from the Supabase dashboard. |

All demo data is fictional. Never put real patient data into the demo.

## How updates reach the demo (CI/CD)

`.github/workflows/ci-cd.yml` runs on every pull request and every push to `main`:

1. Builds and tests the server (`mvn verify` against Postgres) and checks that its Docker image builds.
2. Builds the web app.
3. On `main` only, when both pass: starts a Render deploy through the deploy hook and waits until
   `https://<api>/actuator/info` reports the commit that was just pushed.
4. Then publishes the web app to GitHub Pages.

So every merge to `main` updates the API first and then the site, and a failing build or test never reaches the demo.
You can also re-run it any time from GitHub → Actions → CI/CD → Run workflow.

Database changes ride along: Flyway applies new migrations when the new server version starts.

## One-time setup (about 20 minutes)

You only paste passwords and keys into Supabase, Render and GitHub settings pages. Never paste them into chat, issues or code.

### 1. Supabase: create the database

1. Go to <https://supabase.com> and choose **Sign in** → **Continue with GitHub**.
2. Click **New project**.
   - Name: `hospitos-demo`
   - Database password: click **Generate a password** and save it in your password manager. You need it in step 2.
   - Region: **Southeast Asia (Singapore)**. The Render server also runs in Singapore, so they sit close together.
   - Plan: Free. Click **Create new project** and wait a minute or two.
3. When the project is ready, click **Connect** at the top of the page and pick **Session pooler**
   (not "Direct connection": Render cannot reach that one). You will see something like
   `postgresql://postgres.abcdefghijkl:[YOUR-PASSWORD]@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres`.
   Note three things from it:
   - **Host**: the part after `@` and before `:5432`, for example `aws-0-ap-southeast-1.pooler.supabase.com`
   - **User**: the part after `postgresql://` and before `:`, for example `postgres.abcdefghijkl`
   - **Password**: the database password you saved

You do not need to create any tables. The server creates them on its first start.

### 2. Render: create the API server

1. Go to <https://render.com> and choose **Get started** → **GitHub**. When GitHub asks which repositories
   Render may see, allow `hospit-hms`.
2. In the Render dashboard click **New** → **Blueprint**, pick the `hospit-hms` repository and click **Connect**.
   Render reads `render.yaml` from the repository and shows the service `hospitos-api`.
3. Render asks for the values that are not in the file. Fill them in:

   | Name | Value |
   | --- | --- |
   | `DATABASE_URL` | `jdbc:postgresql://<Host from step 1>:5432/postgres?sslmode=require` |
   | `DATABASE_USER` | User from step 1, for example `postgres.abcdefghijkl` |
   | `DATABASE_PASSWORD` | The Supabase database password |
   | `ADMIN_PASSWORD` | A password for the super administrator `superadmin@hospitos.demo`. At least 10 characters with a letter and a number. Keep it to yourself. |
   | `DEMO_PASSWORD` | The password you will give demo visitors for the role sign-ins. At least 10 characters with a letter and a number. |

   `JWT_SECRET` and `SECRET_KEY` are generated by Render automatically.
4. Click **Apply**. The first build takes 5 to 10 minutes.
5. Open the service. Its address is at the top, for example `https://hospitos-api.onrender.com`
   (Render may add a few letters to the name). Open `<that address>/actuator/health` in your browser;
   it should show `{"status":"UP"}`.
6. In the service go to **Settings** → **Deploy Hook** and click **Copy**. Treat this link like a password:
   anyone who has it can redeploy your server.

### 3. GitHub: connect the pipeline

In <https://github.com/subashbalasubramaniam2905/hospit-hms> go to **Settings** → **Secrets and variables** → **Actions**.

1. **Secrets** tab → **New repository secret**
   - Name: `RENDER_DEPLOY_HOOK_URL`
   - Secret: the deploy hook link from step 2.6
2. **Variables** tab → **New repository variable**
   - Name: `HOSPITOS_API_URL`
   - Value: the Render address from step 2.5, for example `https://hospitos-api.onrender.com`
3. **Settings** → **Pages** → under **Build and deployment** set **Source** to **GitHub Actions** (skip if it already is).
4. **Actions** → **CI/CD** → **Run workflow** → **Run workflow**. When it finishes, open
   <https://subashbalasubramaniam2905.github.io/hospit-hms/>.

If the Render address ever changes, update `HOSPITOS_API_URL` and add the new site origin to `CORS_ORIGINS` on Render
if the site address changes too.

The role accounts are reset to `DEMO_PASSWORD`, unlocked and re-activated every time the server starts (after each deploy and
after it wakes from sleep). To change the demo password, change `DEMO_PASSWORD` in Render → the service → **Environment**;
Render restarts the server and every role account takes the new password. The super administrator password is only used on the
very first start; change it later from the app (profile menu → change password).

## When something goes wrong

- **The site says "Starting the demo server" for a long time.** The free server is waking up. If it takes more than two minutes,
  open the Render dashboard and check the service's **Logs**.
- **Render log shows a database connection error.** Check `DATABASE_URL`, `DATABASE_USER` and `DATABASE_PASSWORD` against
  Supabase → **Connect** → **Session pooler**. If the Supabase project was paused, open it and click **Restore**.
- **The CI/CD run fails at "Wait until Render runs this commit".** The Render build failed or took over 20 minutes.
  Open the deploy on Render to see why, fix it, and push again.
- **The CI/CD run shows "RENDER_DEPLOY_HOOK_URL is not set".** Add the secret from step 3.1.
- **The site still shows the prototype with the role picker.** The `HOSPITOS_API_URL` variable is missing; add it (step 3.2) and re-run the workflow.
